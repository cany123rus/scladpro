# Прокси к Supabase на Cloud Run

Короткие запросы к данным (REST, Auth, Storage, Functions) идут через этот сервис — адрес в `VITE_SUPABASE_REST_URL`.
**Realtime (вебсокеты) здесь отключён**: открытое соединение Cloud Run считает активным запросом, и в сентябре–октябре
именно оно дало счёт около $39 (490 часов инстанса). Реалтайм ходит через Cloudflare-воркер (`VITE_SUPABASE_URL`).
Включить вебсокеты обратно: переменная `ALLOW_WS=1` (не нужно, если на фронте задан `VITE_SUPABASE_URL` с Cloudflare).

## Что уже сделано в коде, чтобы платить меньше
- Соединение с Supabase держится живым (`keepAlive`): второй и следующие запросы идут в ~5 раз быстрее (0,14 с против 0,78 с),
  а Cloud Run платит за время открытого запроса.
- Зависший ответ Supabase обрывается через `UPSTREAM_TIMEOUT_MS` (по умолчанию 30 с), а не висит минутами.
- Вебсокеты отклоняются сразу (426).

## Развёртывание с настройками под бесплатный лимит
Бесплатно в месяц (уточните актуальные цифры на странице тарифов Cloud Run): 2 млн запросов, 360 тыс. GiB-секунд памяти,
180 тыс. vCPU-секунд, 1 GiB исходящего трафика из Северной Америки. Запросы данных — десятки–сотни миллисекунд, поэтому в лимит
укладываются, если сервис не держит соединения и не работает вхолостую.

```bash
cd cloud-run-supabase-proxy
gcloud run deploy supabase-proxy \
  --source . \
  --region europe-north1 \
  --allow-unauthenticated \
  --cpu 1 --memory 256Mi \
  --min-instances 0 \
  --max-instances 3 \
  --concurrency 80 \
  --timeout 60 \
  --cpu-throttling \
  --set-env-vars UPSTREAM=https://blygwkxjogmioebutiwn.supabase.co
```

- `--min-instances 0` — не платить за простой (всегда включённый экземпляр стоит денег даже без запросов).
- `--max-instances 3` — потолок на случай шторма запросов или зацикленного клиента.
- `--timeout 60` — запрос не может висеть дольше минуты (по умолчанию 5 минут).
- `--cpu-throttling` — CPU выдаётся только пока идёт запрос (оплата по запросам, а не по времени жизни экземпляра).
- `--concurrency 80` — один экземпляр обслуживает до 80 запросов сразу: время делится между ними.

## Как смотреть расход
- Google Cloud Console → **Cloud Run → supabase-proxy → Метрики**: «Количество запросов», «Время выставления счетов экземпляра»
  (billable instance time), «Трафик исходящий». Если растёт «Время выставления счетов» при малом числе запросов — открыты долгие соединения.
- **Биллинг → Отчёты**, фильтр по сервису «Cloud Run»: отдельно «CPU», «Memory», «Requests», «Networking».
- Поставьте **бюджет с оповещением** (Биллинг → Бюджеты и оповещения), например 1 $: письмо придёт, пока счёт ещё копеечный.
